# Work required for an installable pilot

Complete the integration path before adding more product breadth. Use fictional
people and one explicitly authorized test address until the full flow is proven.

## 1. Connect and prove the runtime

- Build the exact release image and run it on an available Plow line.
- Verify persistent volume ownership, the CLI, a real model reply and a restart.
- Identify the actual calendar/mail tools and their authenticated accounts.
- Establish whether their real permission model permits unattended sends.
- Record the image digest, commit and observed results without secrets.

**Done when:** a new install answers a text and preserves configured state after
restart. A successful container build alone does not satisfy this requirement.

## 2. Make onboarding conversational and observable

- Collect organization/timezone, exact calendar scope and verified sender/audience.
- Import a short current handbook and reviewed role-specific dress rules.
- Collect volunteer opt-in, roles, skills, capacity and explicit availability.
- Show one concise remit summary and a useful next-event preview.
- Explain missing connections and unresolved source details in plain language.

**Done when:** a fresh owner can set up a fictional club through conversation
without editing JSON, and the stored settings match the instructions. Public
member access stays out of scope until authenticated tool/identity separation
exists; the current deployment is the Guardian's trusted assistant.

## 3. Prove one autonomous cycle

- Use a complete, expanded and paginated calendar scope, including a deliberate
  unrelated personal event that must stay excluded.
- Answer “What do I wear?” with event/role/date-specific public evidence.
- Import todo items and allocate eligible opted-in volunteers.
- Install one runtime scheduler job with actual tool permissions.
- Send one authorized test reminder and assignment notice, retain real receipts,
  and rerun without duplicate delivery.
- Exercise event cancellation, source conflict, cadence removal, pause, verified
  decline/reassignment, completion, unavailable provider and uncertain delivery.

**Done when:** the observed provider payloads/receipts and queue agree; spoofed
replies cannot mutate assignments; ambiguous sends are reconciled, not retried.
Use the live scenarios in [ACCEPTANCE.md](ACCEPTANCE.md). If the provider demands
per-send approval, report unattended sending unavailable on that connection.

## 4. Finish release assets and publish

- Review/merge audit fixes and pass automated checks on the exact release commit.
- Make source and the release image public when deliberately publishing.
- Record a short working demo and at least one actual-agent image, with fictional
  data and no credentials, membership content or identifying personal details.
- Verify slug ownership and accepted usage from genuine model activity.
- Register the video, image and install URL; request organizer verification and
  initial one-click admission through the documented official process.

**Done when:** a new user can follow the published install guide and the Index
shows the required listing/usage/media/verification. No command attempt or local
fixture is a substitute for those receipts.

## Follow-up engineering

- Restrict the development proxy's accepted Host values and exercise its Caddy
  configuration against the pinned proxy version.
- Add explicit schemas and limits for all nested CLI inputs; distinguish invalid
  caller data from programmer errors without exposing tracebacks.
- Decide and implement a separate task-message daily budget if needed; the
  existing setting limits event reminders only.
- Define a dedicated correction/reconciliation workflow for delivered notices,
  changed assignments and unsent notices with stale sender/recipient fields.
- Add freshness/provenance review for general knowledge, source extraction tests
  for tables/PDFs, and realistic retrieval/model-answer evaluations.
- Keep actions/dependencies reviewed and pin CI actions to verified commits when
  adopting a managed update workflow. Document retention and private backup/restore.
